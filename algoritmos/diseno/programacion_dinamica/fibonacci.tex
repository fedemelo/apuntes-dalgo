\subsection{Sucesión de Fibonacci}

Recuérdese la definición de la \hyperref[sec:fibonacci_recursiva]{sucesión de Fibonacci}: 
\begin{align*}
    F(0) &= 0 \\
    F(1) &= 1 \\
    F(n) &= F(n-1) + F(n-2) \quad \text{para } n > 1
\end{align*}

\subsubsection{Subestructura óptima}

De entrada se puede ver la subestructura óptima en la fórmula: la solución, $F(n)$, se construye a partir de las soluciones para dos subproblemas, $F(n-1)$ y $F(n-2)$. Con eso en mente, será viable utilizar programación dinámica.

\subsubsection{Subproblemas superpuestos}

No es difícil ver que el problema presenta subproblemas superpuestos: para calcular $F(n)$ se necesitan calcular $F(n-1)$ y $F(n-2)$; para calcular $F(n-1)$ se necesitan calcular $F(n-2)$ y $F(n-3)$. En tan solo dos pasos, ya se repitió el cálculo de $F(n-2)$ dos veces. 

En el árbol de ejecución de $F(6)$ resulta evidente la cantidad de funciones que se ejecutan dos veces: los subárboles resaltados en rojo, ambos correspondientes a $F(4)$, calculan exactamente lo mismo de forma independiente. Lo mismo sucede con los tres subárboles que resuelven \(F(3)\) y con los cinco subárboles que resuelven \(F(2)\):

Otro factor que permite sospechar la existencia de problemas superpuestos es que el costo computacional del algoritmo recursivo es muy elevado: \hyperref[sec:complejidad-temporal-fibonacci]{exponencial}.

\subsubsection{Solución top-down}
\label{sec:fibonacci_top_down}

Una primera optimización es utilizar programación dinámica top-down.

Se crea un arreglo donde se memoizarán las respuestas. La enésima posición corresponde al cálculo del enésimo número de Fibonacci. Inicialmente se llena con $-1$ para indicar que no se ha computado ningún número.

La función principal pasa el arreglo a la función auxiliar, que es la misma función recursiva anterior, con dos diferencias: memoiza el cálculo si aún no está en el arreglo y retorna la solución memoizada.
\begin{codeblock}[Fibonacci top-down.][impl:fibonacci_top_down]
\begin{pseudocode}
def fibonacci_top_down(n: int) -> int:
    memo = |\textrm{arreglo de enteros de tamaño }$n+1$|
    |\br{cbi}|memo[0] = 0
    memo[1] = 1|\br{cbf}|

    |\br{lli}|for i=2 to n:
        memo[i] = -1|\br{llf}|

    return _fibonacci_memo(n, |\bxl{auxf}|memo)|\bxr{auxf}|

def _fibonacci_memo(n: int, memo: arreglo[int]) -> int:
    |\bxl{memo}|if memo[n] < 0:|\bxr{memo}|
        memo[n] = (
            _fibonacci_memo(n - 1, memo) + 
            _fibonacci_memo(n - 2, memo)
        )
    |\bxl{rmemo}|return memo[n]|\bxr{rmemo}|
\end{pseudocode}
\begin{annotations}
    \codebrace{cbi}{cbf}{Se añaden los casos base directamente al arrreglo}
    \codebrace[width=9cm]{lli}{llf}{Se llena el resto del arreglo con -1, que indica que no se ha calculado ese término de la secuencia. Es inambiguo porque los términos calculados serán positivos}
    \codebox[width=4.5cm]{auxf}{La función auxiliar recursiva recibe siempre la misma estructura y la va llenando}
    \codebox[width=10cm]{memo}{La estructura aún no contiene la solución para este valor, entonces, se memoiza}
    \codebox[width=6.5cm]{rmemo}{Se retorna siempre el valor memoizado (que puede que se haya calculado en ese llamado recursivo o en uno anterior)}
\end{annotations}
\end{codeblock}

Con esa implementación, cada valor solo se calcula la primera vez que se necesita; toda llamada posterior retorna inmediatamente la respuesta ya memoizada. El árbol de ejecución se reduce al siguiente:

\subsubsection{Solución bottom-up}
\label{sec:fibonacci_bottom_up}

El método bottom-up resuelve primero los problemas más pequeños. En este caso, eso traduce naturalmente a calcular primero los menores términos de la sucesión, o lo que es lo mismo, a calcularlos en orden:

\begin{codeblock}[Fibonacci bottom-up.][impl:fibonacci_bottom_up]
\begin{pseudocode}
def fibonacci(n: int) -> int:
    tab = |\textrm{arreglo de }|int|\textrm{ de tamaño }$n+1$|
    tab[0] = 0
    tab[1] = 1

    for i=2 to n:
        tab[i] = tab[i-1] + tab[i-2]

    return tab[n]
\end{pseudocode}
\end{codeblock}

Se obtiene un algoritmo cuya complejidad temporal es $\Theta(n)$. 

Para calcular el enésimo número de Fibonacci es necesario calcular todos los anteriores. Por ende, el algoritmo bottom-up es (ligeramente) más eficiente que el algoritmo top-down: ambos calculan todos los términos anteriores, pero el bottom-up evita el \hyperref[sec:sobrecosto_recursion]{sobrecosto de la recursión}.

\subsubsection{Optimización en espacio}
\label{sec:fibonacci_bottom_up_optimizada}

Nótese que solo se necesitan las últimas dos soluciones para computar la próxima. La tabulación se puede realizar entonces empleando solo dos variables en lugar de un arreglo. 

Eso hace que la complejidad espacial no dependa del tamaño de la entrada, reduciéndola de $\Theta(n)$ a $\Theta(1)$.

\begin{codeblock}[Fibonacci bottom-up optimizado en espacio.][impl:fibonacci_bottom_up_espacio]
\begin{pseudocode}
def fibonacci(n: int) -> int:
    if n <= 1: return n

    prev_prev_sol = 0
    prev_sol = 1

    for i=2 to n:
        solution = prev_sol + prev_prev_sol
        prev_prev_sol = prev_sol
        prev_sol = solution

    return solution
\end{pseudocode}
\end{codeblock}
